# Loki — نسخه پایدار هسته (V1.0)

این بسته بر پایه فایل‌های پروژه ارسالی ساخته شده و اصلاحات محدود و هدفمند زیر روی آن اعمال شده است.

## اصلاحات انجام‌شده
- یکسان‌سازی نسخه منابع HTML، Manifest و Service Worker برای جلوگیری از کش قدیمی.
- اصلاح بازیابی IndexedDB: نسخه‌های جدید Snapshot مهمان را با کلید `guest` ذخیره می‌کنند؛ بازیابی قبلاً فقط کلید قدیمی `main` را می‌خواند. اکنون هر دو کلید پشتیبانی می‌شوند.
- اصلاح تشخیص «پس‌فردا» تا قبل از «فردا» بررسی شود.
- پشتیبانی از ارقام فارسی و عربی در ورودی دستیار و اعتبارسنجی ساعت.
- مقاوم‌تر کردن ذخیره محلی در برابر خطای فضای ذخیره‌سازی.
- اعتبارسنجی بهتر فایل پشتیبان هنگام بازیابی.
- افزودن fallback پوسته برنامه برای بازکردن مسیرها در حالت آفلاین.
- افزودن قوانین Firestore با محدودیت دسترسی هر کاربر به مسیر UID خودش.

## انتشار روی Netlify
1. محتوای همین پوشه را در ریشه مخزن GitHub قرار بده.
2. مطمئن شو فایل `index.html` در ریشه انتشار باشد.
3. Netlify را به مخزن متصل کن یا Deploy جدید انجام بده.
4. پس از انتشار، یک‌بار برنامه را با اینترنت باز کن تا Service Worker نسخه جدید را دریافت کند.
5. اگر نسخه قدیمی نمایش داده شد، برنامه نصب‌شده را کامل ببند و از مرورگر یک بار سایت را با تازه‌سازی کامل باز کن.

## تنظیم Firebase
برای کارکرد حساب و همگام‌سازی ابری:
1. در Firebase Authentication، روش Email/Password را فعال کن.
2. Firestore Database را ایجاد کن.
3. از Firebase CLI و پروژه صحیح استفاده کن و `firebase deploy --only firestore:rules` را اجرا کن تا `firestore.rules` منتشر شود.
4. برای Push، Web Push certificate (VAPID key) باید با مقدار تنظیم‌شده در `app.js` هماهنگ باشد.
5. دامنه Netlify باید در فهرست Authorized domains مربوط به Firebase Authentication باشد.

## محدودیت‌هایی که هنوز نیازمند سرویس بیرونی هستند
- یادآوری‌های زمان‌بندی‌شده در زمانی که برنامه کاملاً بسته است، به زمان‌بند سمت سرور نیاز دارند. دریافت Push آزمایشی به‌تنهایی زمان‌بندی خودکار تسک‌ها را ایجاد نمی‌کند.
- دستیار فعلی پردازش دستورات ساده و قواعدمحور دارد؛ مدل زبانی/هوش مصنوعی مکالمه‌ای به API امن سمت سرور نیاز دارد. کلید API مدل را داخل JavaScript مرورگر قرار نده.
- این بسته شامل Cloud Functions یا سرویس زمان‌بندی نیست.
- عملکرد واقعی ورود، Firestore و Push باید با تنظیمات Firebase و دامنه منتشرشده آزمایش شود؛ کد کلاینت به‌تنهایی مجوزها و پیکربندی کنسول را اثبات نمی‌کند.
